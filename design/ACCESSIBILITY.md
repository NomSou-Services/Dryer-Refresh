# Accessibility Contract

Baseline target: WCAG 2.2 AA for applicable public web experiences.

## Required checks

- semantic landmarks and HTML
- logical heading hierarchy
- keyboard operability
- visible focus
- accessible names for controls
- labels and instructions for form fields
- programmatic error association
- meaningful alternative text
- decorative images hidden appropriately
- sufficient text and UI contrast
- no information conveyed by color alone
- touch targets sized and spaced appropriately
- correct dialog focus management
- logical DOM and reading order
- reduced-motion support
- accessible loading, success, empty, and error feedback
- zoom/reflow without loss of core functionality
- no keyboard traps

Automated tools are useful but are not proof of accessibility. Manual keyboard and screen-reader-aware review remains necessary.
