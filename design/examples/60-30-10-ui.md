# 60/30/10 UI Examples

These examples mirror the starter implementation and are intended for Grok, Figma handoff, and human review.

## Page composition

```text
DOMINANT / 60%
Hero + normal page canvas
bg-dominant text-dominant-foreground

SECONDARY / 30%
Supporting section
bg-secondary text-secondary-foreground

STRUCTURAL SECONDARY
CTA panel / footer
bg-brand text-brand-foreground

ACCENT / 10%
Primary actions and focal details
bg-accent text-accent-foreground
text-accent
```

## Hero

```tsx
<section className="bg-dominant text-dominant-foreground">
  <p className="text-accent">Eyebrow</p>
  <h1 className="text-brand">Primary headline</h1>
  <ButtonLink href="/contact">Start a project</ButtonLink>
</section>
```

The dominant canvas does most of the visual work. Accent is limited to the eyebrow and primary action.

## Supporting section

```tsx
<section className="bg-secondary text-secondary-foreground">
  <article className="bg-surface">
    <div className="bg-accent" aria-hidden="true" />
    <h3 className="text-brand">Feature</h3>
  </article>
</section>
```

Secondary color creates section separation. Surface cards remain quiet; the accent marker is intentionally small.

## CTA

```tsx
<section className="bg-dominant">
  <div className="bg-brand text-brand-foreground">
    <ButtonLink href="/contact">Contact us</ButtonLink>
  </div>
</section>
```

The brand panel is a structural supporting color. The button remains accent-colored so the action stays visually dominant inside the panel.

## Buttons

Primary:

```text
bg-accent text-accent-foreground
```

Secondary:

```text
border-border bg-surface text-dominant-foreground
hover:bg-secondary
```

Do not make every button accent-colored. Accent scarcity is what gives the primary action its hierarchy.

## Accessibility exception

If a chosen brand color does not provide sufficient contrast, adjust the token values. Do not preserve a ratio or client-provided swatch at the expense of readable text, visible focus, or understandable state feedback.
